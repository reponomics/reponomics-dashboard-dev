How Privacy Works

Three ways to deploy your traffic dashboard — from fully public to encrypted. No external services, no auth providers. Just GitHub.

Choose your deployment mode

✓ Live URL
~ Key-protected
✓ Real encryption (AES-GCM)
✓ No external services
How encrypted mode works
Step 1 — Build

GitHub Action

Renders the dashboard HTML, then encrypts the entire payload using your dashboard key

AES-GCM 256-bit
Step 2 — Publish

GitHub Pages

Publishes only the encrypted ciphertext + a dashboard key input form. No plaintext data is embedded in Pages.

PBKDF2 key derivation
Step 3 — View

Browser

Viewer enters the dashboard key. Web Crypto API decrypts locally. The dashboard key never leaves the browser.

Web Crypto API

This means: Encrypted mode protects the Pages payload and, for public repositories, the retained Actions data artifact when the dashboard is not otherwise public. Public README summaries remain public if you enable them.
Threat model — honest version

Protects against

  • Casual visitors who guess or find your Pages URL
  • Bots and search engine crawlers
  • Someone sharing the link without the dashboard key
  • Automated scraping of public GitHub Pages

Does not protect against

  • Brute-force of a weak dashboard key (page can be downloaded)
  • Anyone with the dashboard key or access to repository secrets
  • Sophisticated or targeted attacks
  • No per-user access, no revocation, no audit log
Not a replacement for enterprise auth. If you need per-user access control, audit logging, or compliance guarantees, use GitHub Enterprise with Pages access restrictions. Encrypted mode is a pragmatic middle ground for indie developers who want a live URL without exposing data to the open web.
